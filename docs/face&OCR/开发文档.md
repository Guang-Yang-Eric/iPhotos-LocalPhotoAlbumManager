# 人脸识别与 OCR 开发文档（实现设计）

## 1. 开发目标
在不影响现有主库入库路径的前提下，实现：
- 人脸检测、embedding、聚类与聚类操作（合并/迁移）
- OCR 提取与文字检索
- FaceDB/OCRDB 双库隔离
- CUDA 加速与公平多 Worker 调度

## 2. 建议模块与文件结构
以下为建议增量结构（以当前 `src/iPhoto` 为根）：

## 3. 开发过程（分阶段）
### Phase 1：数据层与队列框架
1. 建立 FaceDB/OCRDB 连接与迁移脚本。
2. 建立独立入库队列（Face/OCR）与主队列解耦。
3. 完成幂等键：`photo_id + algorithm_version + file_hash`。

### Phase 2：人脸链路
1. OpenCV 检测（DNN/Cascade 兼容层）。
2. embedding 生成与版本化入库。
3. 聚类策略（推荐 HDBSCAN/DBSCAN 或阈值层次聚类）。
4. 实现聚类操作：
   - 合并聚类：更新成员与中心点
   - 单张迁移：移动 member 并重算两侧中心

### Phase 3：OCR 链路
1. 图像预处理（灰度、去噪、倾斜矫正）。
2. OCR 提取文本块并写入 `ocr_blocks`。
3. 分词与归一化，写入 `ocr_tokens`。
4. 实现关键词检索并映射回 `photo_id`。

### Phase 4：性能与稳定性
1. CUDA 探测、GPU/CPU 双路径。
2. 公平调度（WFQ/DRR）与背压。
3. 失败重试、死信队列、重算任务。

## 4. 信号流（Signal Flow）

```text
PhotoImported(photo_id)
  ├─ emit -> MainIngestCompleted(photo_id)
  ├─ emit -> FaceTaskEnqueued(photo_id)
  └─ emit -> OcrTaskEnqueued(photo_id)

FaceWorkerDone(photo_id, cluster_updates)
  └─ emit -> FaceIndexUpdated(photo_id)

OcrWorkerDone(photo_id, tokens)
  └─ emit -> OcrIndexUpdated(photo_id)
```

关键要求：Main 信号链路不等待 Face/OCR 完成；Face/OCR 失败只重试各自链路。

## 5. 数据流（Data Flow）

### 5.1 人脸数据流
```text
Photo -> Detect Faces -> Face Detections -> Embeddings -> Cluster Assign -> FaceDB
```

### 5.2 OCR 数据流
```text
Photo -> Preprocess -> OCR Blocks -> Tokenize/Normalize -> OCRDB Index
```

### 5.3 检索数据流（按文字搜图）
```text
Query Text -> Normalize/Tokenize -> Match ocr_tokens -> Join ocr_images -> photo_id list
```

## 6. 关键实现细节
1. **聚类合并**
   - 输入：`cluster_a`, `cluster_b`
   - 操作：成员并集合并、重新计算 centroid、写 `face_cluster_operations`。
2. **单张迁移**
   - 输入：`embedding_id`, `src_cluster`, `dst_cluster`
   - 操作：删除旧关联、插入新关联、重算两边 centroid。
3. **版本化**
   - 模型版本字段必须写入每条检测/embedding/OCR 记录，便于重算与回滚。
4. **公平调度**
   - 每轮从 Face/OCR 队列按权重取任务，单任务 GPU 时间片超阈值则让出调度。

## 7. 测试方案与测试集
### 7.1 单元测试
- 人脸框坐标合法性、embedding 维度校验
- 聚类合并/迁移后的成员数量与中心点正确性
- OCR token 归一化与检索召回逻辑

### 7.2 集成测试
- 单图多脸 + OCR 并行入库
- 主队列高压下 Face/OCR 积压与恢复
- CUDA 不可用场景自动降级

### 7.3 回归测试集建议
1. 人脸集：多人同场景、遮挡、侧脸、低光。
2. OCR 集：中文、英文、数字混排，旋转与模糊样本。
3. 性能集：1k/10k 图片规模，观测吞吐与延迟。

## 8. 验收与发布建议
1. 先灰度开启 OCR，再开启人脸聚类（按功能开关）。
2. 先启用 CPU 路径验证正确性，再启用 CUDA 路径压测。
3. 发布前导出 FaceDB/OCRDB schema 快照并留档。
