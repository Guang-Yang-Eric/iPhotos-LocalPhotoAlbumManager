# 人脸识别与 OCR 能力需求文档（OpenCV 方案）

## 1. 背景与目标
参考成熟开源相册（如 Immich、PhotoPrism、LibrePhotos）及行业惯例，为 iPhotos 增加独立于主库的：
- 人脸检测、特征提取、人物聚类
- OCR 文字识别与可检索入库
- CUDA 加速与公平资源调度

目标是保证新增能力可扩展、可回溯、可重算，且不影响主队列对主库的写入与响应。

## 2. 范围
### 2.1 In Scope
1. 基于 OpenCV 的人脸检测（优先 DNN/ONNX 模型接入）与特征向量提取。
2. 人脸聚类、聚类合并、单图迁移聚类、聚类重算。
3. OCR（中文/英文）文本提取与文本索引入库。
4. 主库之外的两个独立数据库：FaceDB、OCRDB。
5. 多入库队列/多 Worker，公平分配 CPU/GPU/IO 资源。

### 2.2 Out of Scope（本期不做）
- 在线训练自定义识别模型
- 跨设备分布式推理
- 对外开放检索 API（先内部能力）

## 3. 功能需求
### 3.1 人脸识别与聚类
1. 支持单图多脸检测，输出边界框、关键点、质量分。
2. 对每张人脸生成 embedding（向量）并保存版本。
3. 支持增量聚类（新图进入时局部更新）和全量重聚类。
4. 支持用户操作：
   - 合并两个聚类
   - 将单张人脸从 A 聚类移入 B 聚类
   - 将图片标记为“忽略人脸”
5. 聚类结果支持“候选同人”置信度展示（用于后续 UI）。

### 3.2 OCR 与文字检索
1. 对图片执行 OCR，提取文本块、置信度、语言信息。
2. OCR 结果入 OCRDB 并建立倒排索引字段（token 化后持久化）。
3. 支持按关键词搜索图片（AND/OR 基础语义）。
4. 支持 OCR 结果版本化（算法版本升级后可重跑并对比）。

### 3.3 调度与性能
1. 主库写入队列优先级最高，不得被 Face/OCR 写入阻塞。
2. Face 队列与 OCR 队列独立，支持多 Worker。
3. 公平性要求：
   - 同级队列使用 Weighted Fair Queuing（WFQ）或 Deficit Round Robin（DRR）。
   - 任一队列长期吞吐占比不低于其权重的 80%。
4. GPU 资源控制：
   - 支持 CUDA 可用性探测与自动降级到 CPU。
   - 单卡并发上限可配置（防止 OOM）。
5. 重试机制：指数退避 + 死信队列（DLQ）。

## 4. 非功能需求
1. **可靠性**：任务幂等（同一 photo_id + 算法版本不可重复写脏数据）。
2. **可观测性**：队列长度、处理时延、失败率、GPU 利用率可监控。
3. **可维护性**：模型版本、阈值、聚类策略可配置。
4. **安全性**：数据库最小权限；OCR 文本与人脸向量仅本地存储。

## 5. 数据库设计（主库之外）

> 命名建议：
> - `iphoto_face.db`（FaceDB）
> - `iphoto_ocr.db`（OCRDB）

## 6. 队列与资源公平分配要求
1. 队列：`main_ingest_queue`、`face_ingest_queue`、`ocr_ingest_queue`。
2. 资源权重（默认）：Main:Face:OCR = 6:2:2，可配置。
3. Worker 规则：
   - Main Worker 独立线程池，不与 Face/OCR 共池。
   - Face/OCR Worker 共享 GPU 调度器，采用公平轮转。
4. 背压策略：Face/OCR 积压时自动降频，不反压主队列。

## 7. 验收标准
1. 主队列吞吐在开启 Face/OCR 后下降不超过 5%。
2. 人脸聚类支持合并与单张迁移，并完整记录审计日志。
3. OCR 关键词检索 Top-N 可返回正确图片集合。
4. CUDA 不可用时系统自动切换 CPU 且功能可用。
5. 两个独立数据库均可单独备份与恢复，不影响主库。
